# senior-year-website-count-down
My first-ever website and my first time using css and html. Used Claude for debugging and some js


It took me forever to figure out how to put my code in github correctly :((((


Okay, holy freak, that was definitely an experience. This was my first time attempting to make a website and, consequently, my first time using css and html. This website counts down to the date 2027-05-29, which is the day my class graduates. It works by getting the time since Jan 1, 1970, and don't ask me why I have no idea, and it gets the time from the same 1970 benchmark(? if that's what it is) to the graduation date I set. To get the time until the graduation date from now, I do one of the most complicated practices known to mankind: subtraction. Then I do all the fun conversions and store the time as days, hours, minutes, and seconds. In my opinion, I think that format is slightly more readable than a bazillion milliseconds —but perhaps that would look more condescending? The decorations took up a majority of the time I spent on this project :( The stars have a rotation, animation, and locational properties; each one generates random numbers in a fixed range. The comets follow a similar process and numbers are randomly generated so that the comets start near the top right of the screen to ensure they are visible, and after a set amount of time, they disappear. Finally, the small button under the countdown, upon click, will create one of 3 random photos in a randomized location on the screen. The first error I ran into was the photos only appearing in the center margin, which I then figured out was due to me not setting a position for them. I figured this out by experimenting with diffrent transformative properties such as scale, rotate, and most importantly locations(like .left, .top, etc). This part is what I had the most difficulty with, as the pictures were not appearing anywhere near the top left of the screen. At this point in the project, this is when ai was used. As it turned out, the photos' positions were being calculated before they were sized down. To fix this, Claude helpfully supplied that I should resize the actual image with .width/.height rather than transform.
